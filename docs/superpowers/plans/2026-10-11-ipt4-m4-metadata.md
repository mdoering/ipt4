# IPT4 M4 (Metadata editors) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The EML metadata editor (14 sections plus logo upload), the Camtrap DP metadata editor and the Frictionless/ColDP data package metadata editor work on IPT4 with IPT 3's templates, validation messages and saved results.

**Architecture:**
- Port `MetadataAction`, `CamtrapMetadataAction` and `DataPackageMetadataAction` with `tools/port/port-action.py` to `web.manage` page beans; a `MetadataController` maps `metadata-{section}`, `camtrap-metadata-{section}`, `datapackage-metadata-{section}` and `uploadlogo`.
- **Working copy** (design §4): on POST a page binds into a deep copy of the resource's metadata (`Eml`, `CamtrapMetadata`, `FrictionlessMetadata`), after IPT 3's `prepare()` list clearing on that copy; only when the section validates is the copy put on the resource and saved, under the resource's lock. IPT 3 bound the live object, so a rejected form left invalid data in memory.
- **Converters:** IPT 3's `*-conversion.properties` become Spring property editors registered by the metadata pages (empty-to-null strings, the multi-pattern `DateFormatConverter`, coordinates, URIs, Camtrap enums).
- **Sanitising:** IPT 3's `SanitizeHtmlFilter` (all parameters: tags stripped, the EML rich-text fields limited to IPT 3's allowed tags) and `XssFieldErrorInterceptor` (flagged fields become field errors, result INPUT) are ported first; they apply to every page (they were missing in M2/M3).

**Tech Stack:** as M3.

**Spec:** `docs/design.md` §4 (form binding on a working copy, binder customisers, SanitizeHtmlFilter) and milestone M4.

## Global Constraints

- Template field names unchanged (`eml.associatedParties[0].address.city`).
- GET followed by an unchanged POST of every section leaves `eml.xml` byte-identical.
- Validation messages as IPT 3 on invalid input.
- 5000-parameter contacts POST works on a real server.
- Binding rules from M3 stay (no shared objects, no files).

## Review Focus

1. **Rejected forms change nothing.** An invalid section POST leaves the resource (memory and disk) as it was. Test: Task 3 `invalidSectionLeavesResourceUntouched`.
2. **HTML in fields.** Plain-text fields lose all tags; rich-text fields keep only IPT 3's allowed tags; flagged fields show IPT 3's message. Test: Task 1 `sanitizing`.
3. **Large forms.** A contacts POST with 5000+ parameters and many list items binds completely (auto-grow limits, Tomcat limits). Test: Task 3 `largeContactsForm` (RANDOM_PORT).
4. **Concurrent edits and publishing.** Saving a section while the resource is being published is refused (locked), and two saves do not interleave lists. Test: Task 3 `lockedDuringPublication`.
5. **Logo upload.** Only images, stored as the resource logo, hostile names ignored. Test: Task 4 `logoUpload`.

### Task 1: Sanitising filter and field errors

- Port `SanitizeHtmlFilter` (servlet filter after DoSuffixFilter) and the field-error step (ActionRunner: flagged parameters become field errors, result INPUT).
- Tests: plain-text and rich-text parameters, flagged message, account form with `<script>` in a name.

### Task 2: Templates, converters, metadata page bases

- Convert `manage/eml/**`, `manage/dp-metadata/**` with `tools/ftl-migrate`; check `macros/metadata*.ftl`.
- Port the converters as property editors; working-copy support in a `MetadataPageSupport` helper.
- Tests: converter round trips (dates in all IPT 3 patterns, coordinates), template parse.

### Task 3: EML metadata editor

- Port `MetadataAction`; `MetadataController` for `metadata-{section}`; working copy; `resource.*` extra fields (`coreType`, `subtype`, `citationAutoGenerated`, infer flags).
- Tests: every section GET + unchanged POST keeps `eml.xml` byte-identical; validation messages per section on invalid fixtures; `invalidSectionLeavesResourceUntouched`; `largeContactsForm`; `lockedDuringPublication`; next-section redirects.

### Task 4: Logo upload

- `uploadlogo` (MetadataAction.uploadLogo) with UploadStore; portal `logo.do` serves it.
- Tests: `logoUpload` (png accepted, non-image refused, hostile name).

### Task 5: Camtrap DP and Frictionless/ColDP metadata editors

- Port `CamtrapMetadataAction`, `DataPackageMetadataAction`; controller mappings; working copies.
- Tests: GET + unchanged POST per section keeps the metadata file identical; validation errors; save.

### Task 6: M4 exit checks

- Crawler follows the metadata editors; authorization matrix includes them; Docker smoke.
