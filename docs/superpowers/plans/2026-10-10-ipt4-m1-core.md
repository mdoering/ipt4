# IPT4 M1 (Core, persistence, importer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move all web-free IPT 3 code into `ipt-core`, cut its Struts, HttpClient 4, Gson and XStream ties, store the data dir as JSON, and add `ipt-legacy-import` with a `migrate` command. A copy of an IPT 3 data dir then migrates, IPT4 boots on it, and headless publishing works.

**Architecture:**
- The port is mechanical first: a script copies the legacy packages verbatim from the baseline, keeping package names, so upstream patches still apply with `git am --directory=ipt-core`.
- Web couplings are then cut with the smallest diff that compiles:
  - `BaseAction` parameters become `Feedback`, an interface that keeps the BaseAction method names core already calls (`getText`, `addActionError`, `addFieldError`, ...). Call sites therefore change only their parameter type.
  - `SimpleTextProvider` becomes a thin core class over `BundleMessages`, with the same method names.
- New code gets new packages: `org.gbif.ipt.{feedback,persistence,job,http}`.
- XStream lives only in `ipt-legacy-import`, which also holds a frozen copy of the IPT 3 model.

**Tech Stack:** As M0, plus the legacy library set (dwca-io, gbif-api, gbif-doi, gbif-metadata-profile-eml, dwc-dp-analyser-lib, frictionless forks, POI, tika, openrtf, digester3, owasp sanitizer, jsoup, JDBC drivers, jakarta.mail, hibernate-validator). Jackson 3 for the data-dir JSON; Jackson 2 stays where legacy code uses it (data package metadata, YAML).

**Spec:** `docs/design.md` (sections 1–3, 6, 8, milestone M1).

## Global Constraints

- **Baseline:** `03582bcf20daa3c27262c2f5e50f0d308db2c2db` of `~/code/gbif/ipt`. Read files with `git -C ~/code/gbif/ipt show "${B}:<path>"`.
- **Packages:** core keeps legacy package names (`org.gbif.ipt.model|service|task|validation|utils|config`, `org.gbif.datapackage`).
- **No web in core:** `ipt-core` must not depend on servlet, Spring MVC, Spring Boot, Struts or Tomcat (enforcer + ArchUnit). `spring-context` is allowed for `@Service`/`@Scheduled`; `spring-web` for `RestClient` only if needed.
- **No XStream in `ipt-core` or `ipt-app`** at the end of M1. Enforced by enforcer in both.
- **No HttpClient 4, gbif-httputils or Gson** anywhere at the end of M1.
- **Data dir v4 layout and JSON shapes** exactly as `docs/design.md` §3.
- **Commits:** conventional style, no AI attribution, on `main`, local only.
- **Tests:** `mvn -B verify` green on JDK 25 after every task. Network tests are tagged `network` and excluded by default.

## Review Focus

1. **Resource graph references.** Users, organisations, extensions, concept terms, schemas, tables, fields, mapping sources and JDBC info are stored as keys and re-linked on load. A data dir whose resource references a missing extension or schema must still load and report it, as IPT 3 does. Test: Task 3 `missingExtensionIsReportedNotFatal`.
2. **Secrets.** SQL source passwords and registration passwords never appear in clear text in JSON; a wrong or missing key file is a clear startup error, not silent data loss. Tests: Task 3 `sqlPasswordIsEncrypted`, `wrongKeyFailsLoudly`.
3. **Partial writes.** A crash mid-save must not leave a truncated `resource.json`. Test: Task 3 `atomicWriteKeepsOldFileOnFailure`.
4. **Migration of odd legacy dirs.** v1 `registration.xml`, pre-2.2.1 `dwca.zip`, resources with version history and DOIs, non-empty target. Tests: Task 6 fixtures.
5. **Re-running migrate.** A second run on the same target refuses; `--dry-run` writes nothing. Tests: Task 6 `refusesNonEmptyTarget`, `dryRunWritesNothing`.

### Task 3: JSON data dir persistence

**Files:** `ipt-core/src/main/java/org/gbif/ipt/persistence/*`, `service/manage/impl/{ResourceManagerImpl,ResourceLoaderImpl}.java`, `service/admin/impl/{UserAccountManagerImpl,RegistrationManagerImpl}.java`, remove `model/converter/**`, `service/manage/impl/{ResourceXStreamFactory,XStreamResourcePersister}.java`, `utils/PBEEncrypt.java` (moves to legacy import in Task 6).

**Interfaces:**
- `DataDirJson.mapper()` → Jackson 3 `JsonMapper`: field visibility only, sorted properties, `FAIL_ON_UNKNOWN_PROPERTIES=false`, indent output, ISO dates. Reference mixins write `User`→email, `Organisation`→key UUID, `Extension`→rowType, `ExtensionMapping` (in property mapping refs)→index, `ConceptTerm`/`Term`→qualified name, `DataSchema`→identifier, `DataPackageTableSchema`→name, `DataPackageField`→`table/field`, `Source`→name, `JdbcInfo`→name; sources polymorphic with `@JsonTypeInfo(property="type")` names `text|excel|sql|url`.
- `AtomicFiles.write(Path, IOConsumer<OutputStream>)`: temp file in the same dir, fsync, `ATOMIC_MOVE`.
- `SecretCipher(Path keyFile)`: `encrypt(String) -> "{aesgcm}" + base64(iv|ct|tag)`, `decrypt(String)`; key from `IPT_SECRET_KEY` (base64) overrides the file; creates a 32-byte key file with mode 600 when absent.
- `JsonResourcePersister implements ResourcePersister` (`resource.json`, `inferred-metadata.json`, `schemaVersion: 1`).
- `ResourceLinker.link(Resource, Feedback)`: replaces key stubs with managed instances; missing extension/schema → warning, mapping kept detached (IPT 3 behaviour).
- `UserStore` (`config/users.json`), `RegistrationStore` (`config/registration.json`).
- `DataDirFormat.check(Path)` → `EMPTY | V4 | IPT3 | UNKNOWN`; marker `ipt-datadir.json` `{"format":"ipt","version":1,"createdBy":...}`.

### Task 6: `ipt-legacy-import` and the `migrate` command

**Files:** `ipt-legacy-import/**`, `tools/port/freeze-legacy-model.sh`, `ipt-app/.../IptApplication.java`.

- The frozen model is generated by `freeze-legacy-model.sh` from the baseline: the model classes reachable from `resource.xml`, `users.xml`, `registration.xml` and the inferred metadata, re-packaged to `org.gbif.ipt.legacy.v3.model`, with validation annotations stripped. Reference converters become key stubs (`UserRef(email)`, `ExtensionRef(rowType)`...).
- `Migrator.migrate(Path from, Path to, Options)` performs design §3 steps 1–9; `MigrationReport` writes `migration-report.{json,txt}`.
- The frozen objects are written with a mapper that applies the same JSON shape as `DataDirJson` (shared field visibility; stubs serialize as keys), so ipt-core reads the output unchanged.
- `LegacyPbe` decrypts IPT 3 PBE secrets (fixed legacy key) — users' legacy PBE passwords are re-hashed with bcrypt; SQL and registration secrets re-encrypted with `SecretCipher`.
- `IptApplication.main(args)`: `args[0]=="migrate"` → `MigrateCommand` without a web context.
