# IPT4 M3 (Manage, without metadata editors) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manager can do on IPT4 everything IPT 3's `/manage` area offers except the metadata editors (M4) and registry/DOI actions (M6): list resources, create them (empty, from DwC-A, EML or data package), add/edit/delete sources, map to extensions or data package schemas, translate values, publish DwC-A and DwC-DP, cancel a publication, change visibility, manage co-managers, version history, publication settings and auto-publishing.

**Architecture:**
- Same pattern as M2: `tools/port/port-action.py` ports each `org.gbif.ipt.action.manage.*Action` to a page bean in `org.gbif.ipt.web.manage`; thin `PageController`s map the IPT 3 URLs (`/manage/<action>`, with and without `.do`) to page methods and IPT 3 results to views/redirects.
- `ManagerBasePage` (port of `ManagerBaseAction`) and a `ManageGuard` (IPT 3 `ResourceSessionInterceptor` + the per-resource part of `RequireManagerInterceptor`): resolve `r` (else the session's resource), 404 (`manage/404.ftl`) for unknown resources, 401 (`manage/401.ftl`) when the user may not manage it, redirect to `/manage/locked.do` while it is being published. Every `/manage` handler that takes a resource goes through it, including IPT 3's unprotected AJAX actions (`cancel`, `peek`, `mappingPeek`, `report`).
- Binding: `ManagerBasePage.getResource()` is **not** bindable (IPT 3 bound the live resource to depth 8, so `resource.creator.role=Admin` was postable). Pages declare the extra paths they bind (`ActionPage.extraAllowedFields()`), and `ActionRunner` refuses any path through a `User`, `Organisation`, `role`, `password`, `key`, `status` or `class` property.
- Uploads: Spring multipart (`MultipartHttpServletRequest`) mapped onto the pages' IPT 3 `File`/`fileContentType`/`fileFileName` setters by a small `Uploads` helper; sizes from `ipt.upload.max-size` (default 10 GB), files in `${data-dir}/tmp/uploads`, Tomcat parameter/part limits raised.

**Tech Stack:** as M2.

**Spec:** `docs/design.md` §4 (controllers, interceptors, uploads, downloads) and milestone M3.

## Global Constraints

- IPT 3 URLs keep working with and without `.do` and with the same parameters (`r`, `id`, `mid`, `s`, `v`, ...).
- Templates: IPT 3 markup converted with `tools/ftl-migrate`; manual edits only where the conversion report or CSRF requires them.
- CSRF on every POST, including XHR/`FormData` uploads (`_csrf` field) and `$.ajax` (header via `csrf.js`).
- No network access in tests; registry calls fail fast.
- Per-resource authorization on every `/manage` handler using `r`; `/manager-api/*` the same.
- M4 (metadata editors), M5 (admin), M6 (registry/DOI) are out of scope; their links may 404 until then.

## Review Focus

1. **Cross-resource access.** Manager A cannot read or change resource B (overview, sources, mappings, publish, cancel, peek, report, raw-source, eml, history, translation) by passing `r=B` or by having B in the session. Test: Task 2 `managerCannotTouchOthersResources` (all manage URLs).
2. **Mass assignment.** No POST to any manage page can change `resource.creator`, `resource.managers`, `resource.status`, `resource.key`, a user's role or password. Test: Task 2 `resourceInternalsAreNotBindable`.
3. **Upload handling.** File names with path parts (`../../x`), oversize files, wrong types and empty uploads never write outside the resource's folder or the upload tmp dir and never 500. Test: Task 5 `hostileUploadNames`.
4. **Publishing state.** A resource being published redirects other manage pages to `locked`; cancel stops it; a failed publication leaves the previous version downloadable. Test: Task 4 `lockedWhilePublishing`, `cancelKeepsPreviousVersion`.
5. **SQL sources.** SQL source passwords are never rendered back in HTML and stay encrypted at rest. Test: Task 5 `sqlPasswordNotRendered`.

### Task 1: Manage templates and shim

- Convert `manage/*.ftl` (except `manage/eml/**`, `manage/dp-metadata/**`: M4) with `tools/ftl-migrate`; add `s.file` to the shim (Struts simple-theme markup).
- Manual: XHR upload in `overview.ftl` sends `_csrf`; `manage/401.ftl`, `manage/404.ftl`.
- Tests: `TemplatesParseTest` covers the new templates; `TemplateShimTest` case for `s.file`.

### Task 2: Manage framework

- Port `ManagerBaseAction` → `ManagerBasePage`; `ManageGuard`; manage result map (`404`, `401`, `cancel`, `home`, `locked`); `ActionPage.extraAllowedFields()` and the forbidden-path rule in `ActionRunner`; `Uploads` helper and multipart configuration.
- Tests: `managerCannotTouchOthersResources` (table of URLs × {anonymous → login, other manager → 401, admin → ok, unknown r → 404}); `resourceInternalsAreNotBindable`; `ActionRunnerTest` forbidden paths.

### Task 3: Manage home, create, manager API, locked/report/cancel

- `HomeAction` (manage/home + `manager-api/resources` JSON), `CreateResourceAction` (empty, DwC-A, EML, data package uploads), `OverviewAction.locked`/`report`/`cancel`, `MetadataAgentSuggesterAction` (`manager-api/suggest-*`).
- Tests: create each kind from fixtures; shortname validation errors; JSON shapes as IPT 3 (`DatatableResult`, suggestions).

### Task 4: Resource overview and lifecycle

- `OverviewAction` without registry/DOI: overview page, `publish`, visibility (`makePublic`, `makePrivate`, `cancelVisibilityChange`), `delete`/`undelete`/`deleteFromIpt`, managers (`addManager`, `deleteManager`), `replace-eml`, `replace-datapackage-metadata`, `updateDwcDpDatasetType`, `mappingPeek`, manage `eml` download, `urlMetadata`.
- Tests: publish DwC-A from overview (job runs, version bumps, archive downloadable); `lockedWhilePublishing`; `cancelKeepsPreviousVersion`; visibility changes; co-manager gains access; delete hides from portal.

### Task 5: Sources

- `SourceAction` (`addsource` file/URL/SQL, `source` edit + analyze, `peek`, `delete-source`, `canceloverwrite`), `raw-source` download.
- Tests: add text/Excel/URL(local fixture server)/SQL(H2 or skipped) sources; overwrite flow; `hostileUploadNames`; `sqlPasswordNotRendered`; delete source used by a mapping gives IPT 3's error.

### Task 6: DwC mapping, translation, vocabulary

- `MappingAction` (`mapping`, `delete-mapping`), `TranslationAction` (+ reload, automap), `vocabulary` popup (`VocabulariesAction` in manage).
- Tests: map the res1 source to occurrence core (auto-mapping, save, filter, ID column), translation round trip, delete mapping.

### Task 7: Data package mapping, field translation, validation report

- `DataPackageMappingAction` (`dataPackageMapping`, source selection/creation, delete), `DataPackageFieldTranslationAction`, `ValidationReportAction`.
- Tests: map a source to a DwC-DP table; publish DwC-DP; validation report renders.

### Task 8: Publication settings, auto-publish, version history

- `PublicationSettingsAction`, `AutoPublishAction`, `VersionHistoryAction` (`history`), manage `detail` (portal resource page for managers).
- Tests: settings saved; auto-publish interval stored and next date shown; version history change summary saved.

### Task 9: M3 exit checks

- End-to-end over MockMvc: create from DwC-A, from EML, from data package; add source; map; publish DwC-A and DwC-DP; cancel; version history; archives semantically equal to M1's IPT 3 expectations.
- Crawler as a manager through `/manage` (except M4/M6 links); authorization matrix test enumerating every `/manage` and `/manager-api` handler from `RequestMappingHandlerMapping`.
