# IPT4 M2 (Public portal, auth, setup) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything an anonymous visitor, a logging-in user and a first-time installer sees works on IPT4 with the IPT 3 templates: portal home, resource pages, downloads, RSS, DCAT, inventory and API JSON, health, about, login/logout/account, the setup wizard, and error pages.

**Architecture:**
- Templates are converted with `tools/ftl-migrate` and rendered unchanged through the M0 FreeMarker setup. The `s` shim grows the tags these templates use (`submit`, `property`, `fielderror`, `select`, `checkbox`).
- Each Struts action becomes a controller plus a page bean (`PageSupport` subclass) exposing the action's getters, so `${action.x}` and bare `${x}` keep resolving.
- `RequestFeedback` (request scoped, flash-backed across redirects) implements core's `Feedback` and feeds `actionMessages`/`actionErrors`/`warnings`/`fieldErrors` to the templates.
- Spring Security's form login posts to `/login` with `email`/`password`, backed by `UserAccountManager`; `SetupGuard` redirects to the setup wizard until setup is complete.
- `SiteConfig` (M0 stand-in for `cfg`) is replaced by core's `AppConfig`.

**Tech Stack:** as M1.

**Spec:** `docs/design.md` §4–5, milestone M2.

## Global Constraints

- Public URLs keep working with and without `.do`, with the same query parameters: `home`, `resource?r=&v=`, `resource/preview?r=`, `eml?r=&v=`, `metadata?r=&v=`, `logo?r=`, `rtf?r=&v=`, `archive?r=&v=`, `publicationlog?r=`, `sourcelog?r=&s=`, `appLogo`, `rss`, `dcat`, `inventory/dataset`, `inventory/v2/dataset`, `api/resources`, `api/health`, `health`, `about`, `login`, `account`, `fallback`.
- Downloads: same content type and `Content-Disposition` filename as IPT 3; `Last-Modified`/`If-Modified-Since` → 304; HEAD supported.
- JSON endpoints: field names and nesting as IPT 3 (golden shapes from `tools/golden`).
- Templates: IPT 3 markup; deviations only as listed in `docs/deviations.md`.
- CSRF on every POST; logout is POST.
- No network access in tests (registry URLs point at a dead port).

## Review Focus

1. **Private and deleted resources.** `resource`, `eml`, `archive` etc. for a private resource return 404 to anonymous users and work for its managers; deleted resources answer 410. Tests: Task 3 `privateResourceIsHiddenFromAnonymous`, `deletedResourceIsGone`.
2. **Hostile input in query parameters** (`r`, `v`, `s`) — path traversal (`s=../../config/users.json`), non-numeric versions, unknown resources — gives 404/400, never a file outside the resource or a 500. Test: Task 4 `sourceLogCannotEscapeTheResource`, `badVersionIs404`.
3. **Login redirects** only go to local paths (no open redirect via `redirectUrl`/saved request). Test: Task 6 `loginNeverRedirectsOffSite`.
4. **Setup wizard** cannot be re-entered once setup is complete (no admin takeover). Test: Task 7 `setupIsClosedAfterCompletion`.
5. **Conditional GET** with a future or malformed `If-Modified-Since` still returns 200 with the file. Test: Task 4 `malformedIfModifiedSinceServesTheFile`.

### Task 1: Template conversion and the remaining Struts tag shim

- Run `tools/ftl-migrate` on `portal/*`, `error/*`, `inc/*`, `macros/*`, `login.ftl`, `account.ftl`, `health.ftl`, `admin/setup_*.ftl` from the baseline into `ipt-app/src/main/resources/templates`; re-run on `about.ftl`/`inc/*` and keep the M0 hand edits.
- Shim additions in `web.support.freemarker`: `SubmitDirective`, `PropertyDirective`, `FieldErrorDirective`, `SelectDirective`, `CheckboxDirective`, each producing the markup Struts 7's simple theme produces (verified against struts2-core 7.3.0 templates in `scratchpad/jars`).
- Tests: `TemplateShimTest` cases per tag (markup equality with Struts output for representative attributes; escaping of values); `TemplatesCompileTest` loads every template under `templates/` without parse errors.

### Task 2: Web feedback and the page model on AppConfig

- `RequestFeedback implements Feedback` (request scope), flash attributes carry messages across `redirect:`; `GlobalModel` exposes `actionMessages`, `actionErrors`, `warnings`, `fieldErrors`.
- `PageSupport` reads `AppConfig` (base URL, colour scheme, analytics, registration) instead of `SiteConfig`; `SiteConfig` removed.
- Tests: `RequestFeedbackTest` (redirect keeps messages once), `GlobalModelTest` updated.

### Task 3: Portal pages

- Controllers/pages for `home`, `resource` (+ `preview` for managers), `fallback`, `about`, `health`, `rss`, porting `HomeAction`, `ResourceAction`, `FallbackAction`, `AboutAction`, `HealthAction`, `PortalBaseAction`.
- `@PortalResource` resolution: unknown → 404 page, deleted → 410, private → 404 unless the user may manage it (`ResourceAccessPolicy`).
- Tests on the M1 fixture data dir (published res1): page renders with title, versions, downloads links; private/deleted/unknown handling; `rss` content type and items.

### Task 4: Downloads, DCAT, app logo

- `ResourceFileController` (eml, metadata, logo, rtf, archive, publicationlog, sourcelog) and `AppFileController` (appLogo), `DcatController`, porting `ResourceFileAction`, `AppFileAction`, `DCATAction`: `ResponseEntity<Resource>` with IPT 3 content types/filenames, `checkNotModified`, HEAD.
- Tests: each download (content type, disposition, body), 304, HEAD, version parameter, traversal and bad input (Review Focus 2, 5).

### Task 5: JSON APIs

- `inventory/dataset` (v1), `inventory/v2/dataset`, `api/resources`, `api/health` with explicit records mirroring the IPT 3 JSON (Struts JSON plugin serialised getters; `excludeNullProperties` for v2), `Cache-Control: no-cache`.
- Tests: JSON shape equals the golden captures in `tools/golden` (keys and types, values from the fixture data dir).

### Task 6: Login, logout, account

- `UserDetailsService` over `UserAccountManager`; form login at `/login` (`email`, `password`), failure re-renders `login.ftl` with the IPT 3 error text; success updates `lastLogin`, redirects to the saved local request or home; logout POST.
- `AccountController` (profile and password change, porting `AccountAction`, `UserValidator`).
- Tests: login success/failure, lastLogin saved, session id rotated, open-redirect refusal (Review Focus 3), account update and password change with validation errors.

### Task 7: Setup wizard and setup guard

- `SetupGuard` (interceptor): until `ConfigManager.setupComplete()`, every page except setup, static assets, login and health redirects to the current setup step.
- Setup steps 2–5 (`setupDefaultAdministrator`, `setupMode`, `setupPublicUrl`, `setupInstallationComplete`), porting `SetupAction`; step 1 (data dir) is gone.
- Tests: fresh data dir walks through all steps to a complete setup; steps are closed afterwards (Review Focus 4).

### Task 8: Error pages and M2 exit checks

- Error controller and exception handlers rendering `error/*.ftl`, `portal/404.ftl`, `portal/410.ftl` with status codes.
- Crawler test: logged out and as admin, follows every link and GET form from `/` within the IPT; no 4xx/5xx (except intended), no FreeMarker errors, no `${`, `<@s`, `[@s` in HTML.
- Registry contract test: the URLs the GBIF registry stores (`archive.do?r=&v=`, `eml.do?r=`, `resource?r=`, `rss.do`, `dcat.do`, `inventory/dataset`) answer as IPT 3 did.
